# Line Studio

通用多人歌曲分词工作台，适用于组合、乐队、翻唱团队、双人合作与自定义阵容。EXO 历史十二人阵容仅为可编辑的可选模板。默认歌曲为原创六人示例，示例时间均为演示估算。

## 使用

1. 导入 TXT、LRC 或 SRT，设置歌曲信息和演唱阵容。
2. 修改成员的角色、语言、演唱标签和个人偏好，选择全员独唱、副歌合唱等规则。
3. 生成风格适配、平衡参与、主唱倾向三套草案，选择一套应用。
4. 逐句修改归属、演唱类型与起止时间；锁定分配后重新生成不会修改该句。
5. 导入本地音频，点击波形定位、调整速度或循环试听所选片段。在“听音校时”按 S 记开始、E 记结束并进入下一句；记录后播放继续，每句校时可单独撤销。
6. 编辑歌词时在句中放置光标，按光标拆句；时间完整时沿用播放位置或生成估算切点。合并要求两句的成员、段落、类型、语言和标签相同，且时间首尾相接。锁定句先解锁并保存。
7. 导出排行 PNG、片段 CSV、彩色歌词 HTML、SRT、ASS 或可恢复的 JSON 项目。PNG 提供预览，文本导出可复制完整内容；剪贴板不可用时可手动复制。

## 统计约定

- 合唱单列：合唱记入 ALL，个人排行不计合唱。个人占比以个人分配总量为分母。
- 参与全计：每位参与者获得演唱区间的完整时长；同一成员的重叠区间去重，个人总量可能超过歌曲时长。
- 共享均分：每个时间区间由不同的活跃成员均分，同一成员的重复声部不额外增加权重。
- 时间不完整：统一切换为句数，避免将有时间和无时间的片段混为秒数。LRC 推断的结束时间和文本估时均标记为估算。
- 全员独唱：要求每位启用成员至少获得一个单独分配的主旋律或 Rap 片段，合唱不能替代。
- 均衡度采用 Jain 指数，包含零分配成员；它不评价唱功和编曲质量。

## 实现与边界

React + TypeScript + Vinext，UI 使用 shadcn/Radix，波形使用 wavesurfer.js。分配由本地确定性的规则引擎执行，结合角色、语言、标签、偏好、负担与邻句连续性。首版不调用在线大模型，不识别成员声音，不自动获取商业歌词，不导出 MP4。

项目草稿保存在当前浏览器的 IndexedDB；音频通过本地 Object URL 播放，不上传，JSON 仅保存媒体名称。预览与复制在本地生成；点击“下载文件”时，仅将该文件内容 POST 到本站下载接口，接口返回附件且不写入文件或数据库，不缓存响应。音频不包含在请求中。定期导出 JSON，换设备时从文件导入，或在“项目 → 粘贴项目 JSON”恢复备份，再导入原音频。全员匹配有搜索上限；复杂的硬规则和现场重叠条件可能找不到草案，应根据明确的冲突提示调整规则。

支持 1–50 位成员、每首歌最多 500 个片段、60 分钟内的时间。成员标签是用户的编曲设定，不代表客观能力评定。仅在浏览器提供 document.modelContext 时注册 WebMCP 读取、生成和批量分配工具；普通浏览器可正常使用全部 UI。

## 开发

要求 Node 22.13+、pnpm。运行 `pnpm install`、`pnpm dev`。检查命令为 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`。

`lib/studio.ts` 包含独立的解析、分配、统计与项目校验，`lib/segment-edit.ts` 处理拆句、合并与逐句校时。35 项测试覆盖重叠统计、独唱覆盖、锁定、硬规则、导入时间、JSON 校验、CSV 公式防护、字符边界、拆合时长守恒、校时记录，以及 HTTP 下载的 Unicode 和二进制保真、非法输入拒绝。
